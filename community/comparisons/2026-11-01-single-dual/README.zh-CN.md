# 同模型单路、双路与独立副本的实测记录

这里的模型统一为 **Qwen3.8-Flash-Next GSQ-RCO IQ3_XXS**。本文重新整理已有记录，没有在本次补充中重跑GPU测试。

必须区分两件事：一个模型跨两张卡，分别接1个/2个请求；两张卡各自运行一个模型副本，同时各接1个请求。第一种已有当前版本的同轮测量；第二种有10月30日的本机实测，但还没有和当前版本做同日同参对照。

## 一个跨卡模型：单请求与双并发请求

两张7900 XTX，26/22层，白金303W、涡轮231W上限；每请求上下文上限131072，实际输入130020token，每请求输出512token。单路使用公开fixture的route0，双路同时使用route0和route1；均为接近128K合成输入、缓存命中后的端到端测速，包含首字等待。

| 同轮使用的版本 | 单请求均值 t/s | 双路请求0均值 t/s | 双路请求1均值 t/s | 双路合计持续 t/s | 合计相对单请求 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原部署二进制 | 122.68 | 79.06 | 79.84 | 156.43 | +27.5% |
| 完整源码重建 | 113.29 | 80.73 | 80.06 | 158.09 | +39.5% |

单请求均测3次。原部署二进制双路测32.73秒、5批，重建版双路测123.07秒、19批。两行分别是各自同轮的单/双路测量；持续时间不同，不能用来证明哪个二进制更快。

每路速度按各请求自己的墙钟计算并取算术平均；合计持续吞吐按整段总输出token/总墙钟计算，含慢路等待和批次间开销，**不能把每路均值简单相加代替合计值**。route0/1是客户端请求编号，不对应某张GPU。

重建版单请求三次为104.08/116.57/119.23 t/s；原部署版为115.92/125.25/126.86 t/s。历史正文的正式验收则为116.48单路、161.08双路合计，使用130037token输入，属于另一轮。

所以，当前实测不是“一卡120，双卡应该240”：单请求已经使用两张卡；增加到两个请求后，每路约80，合计约156–158，总吞吐提升约27.5%–39.5%，单请求完成速度则下降。以上仅适用于这组输入和配置，不是一般业务保底。

## 两卡各跑一份模型：已有的历史实测

2026-10-30的 `replica-pin12-q6`，每张卡一个独立引擎、各自solo MTP，共享约39.97GiB主机专家arena；每路上限131072，实际每请求输入130041token、输出512token，64GB主机（系统可见约61.51GiB）。白金303W、涡轮257W，队列6、每引擎arena锁页上限12GiB、每引擎会话缓存预算4096MiB。

| 历史独立副本指标 | 实测 |
| --- | ---: |
| 持续双路批次数 | 23批 |
| 各批合计吞吐的中位数 | 132.87 t/s |
| 23批总输出/各批墙钟之和 | 130.88 t/s |
| 路0/路1各自端到端速度中位数 | 86.96 / 66.49 t/s |
| 冷128K请求的两路平均首字等待 | 58.52秒 |
| 整个候选阶段最低可用主存 | 4.27 GiB |

23批墙钟之和179.96秒。130.88这项排除了批次间控制器间隔，不能冒充当前测速脚本按整段时间统计的持续吞吐；132.87则是批次速度中位数，也不是相同统计量。单路解码窗口曾记录104.34/73.46 t/s，但该窗口排除首字，因此不放进端到端表混比。

这些是本机实际数据，不是网友成绩。**不能直接拿132.87和现在161.08相除，宣称跨卡方案固定领先多少**：两轮日期、二进制、前缀、功耗上限、缓存预算、锁页策略和统计方法都有差异。

## 目前能回答与尚缺的对照

现有记录能说明：当前跨卡模型从1请求到2请求能增加合计吞吐；独立双副本也已经跑通过，但在本机64GB配置上余量较紧。不能据此判定128GB主机上哪种架构最划算，也不能推出增加内存必然提速。

要回答评论中的“128GB+双XTX，独立双实例还是一个跨卡模型更有效益”，还缺同日、同一权重和输入、同采样与功耗的完整架构A/B：白金单卡、涡轮单卡、双独立副本、跨卡单/双请求。还需一起记录冷首字、缓存命中、每路及合计端到端速度、峰值显存、主存和长时间稳定性。当前机器没有128GB实机记录；本次不补写未测成绩。

原始数值和推导口径见[data.json](data.json)。当前两版的逐请求原始记录见[原部署版](../../results/production-control.json)和[源码重建版](../../results/clean-source-benchmark.json)。data.json另附历史双副本23批的数值字段、原始文件SHA256；已去除正文、绝对路径和无关进程信息。标记检查通过只说明基本输出检查，不代表全面模型质量评测。
